## ローカル期限試験

`python -B benchmarks/stage1b-readiness/probe_curl_deadlines.py` を実行する。外部接続を行わず、四つのループバック対照で `--connect-timeout 10` と `--max-time 25` を検査する。接続対照はTCP接続後にTLS応答を止め、合計期限対照はHTTP 200応答を途中まで送って止める。それぞれ `curl` の終了コード、観測したHTTP status、本文バイト数、単調時計の経過時間を出力する。遅延側はサーバーが接続クローズを観測し、`curl` の終了は子プロセスの回収で確認する。

ローカル観測窓はプロセス起動・回収やスケジューリングの遅延を含む。実測の25秒上限にはその許容幅を適用しない。部分応答にHTTP 200が含まれても、期限終了時の断片は正常本文の証拠に使わない。実行期限と回収時刻の関係が未解決の間は開始HOLDとする。

実行環境はLinux、Python 3.12.14、curl 8.14.1。四つの対照は期待値と一致した。

| 対照 | curl終了コード | HTTP status | 本文バイト数 | 子プロセス起動・回収を含む経過秒 |
|---|---:|---:|---:|---:|
| 正常応答 | 0 | 200 | 2 | 0.008712 |
| 不存在応答 | 0 | 404 | 0 | 0.008720 |
| TLS接続待ち | 28 | 未取得 | 0 | 10.010729 |
| 本文受信途中 | 28 | 200 | 1 | 25.011702 |

起動から回収までを25秒以内に収める保証は未確認。上の25.011702秒を実測票の操作時刻差にそのまま記録すると、既存の厳格な25秒上限を超える。REAL adapterの設計時に、計測境界を明記して実行上限と回収を確認する。

基準版のオフライン回帰は、整合性検査、合成85/85、公開Schema 98/98、manifest変異5/5、コピー先拒否2/2、002回帰25/25が成功した。
