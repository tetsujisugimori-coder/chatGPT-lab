# Stage 1-B Codex Local ローカル停止・回収試験計画

対象は Draft PR #9、開始 HEAD `6e46e2d00ebeb8062d6ed16807f90a075e788153`。比較 ID は CODEX-LOCAL 候補。共通ベンチマークの固定対象・順序・接続10秒・合計25秒・判定基準は Stage 1-A v0.1.4 に従う。今回は登録実測と第3実験を保留したまま、合成環境で制御可能性を測る。

## 経路と管理

Codex Desktop のローカル PowerShell から Python 監督プロセスを起動する。予備試行のループバック TCP 接続は WinError 10013 で拒否された。監督と読取の間で、Windows の匿名パイプ2本に HTTP フレームを流す一種類の読取経路に切り替える。固定の合成 CONNECT 成功応答を受信してから GET を発行し、同じパイプで固定応答を返す。名前解決・転送・ソケット通信は発生しない。接続待ち対照の注入点は CONNECT 応答の待機であり、匿名パイプのハンドル自体は起動時に渡す。TCP/TLS の接続期限は今回の IPC 結果の適用外。

各読取は新規の無名 Job Object に閉じ込める。読取プロセスを suspended かつコンソールから分離して生成し、Job に登録してから再開する。継承リストはパイプの読取側2ハンドルのみ。KILL_ON_JOB_CLOSE を有効にし、ブレークアウェイを指定しない。子起動ケースは Python の子を1つ生成する。PID・PPID に加え、保有ハンドルの Job 所属・サイン・終了コードと、Job の累計・稼働数を照合する。Job を空にしてから確認済みハンドルを閉じる。Job 登録に失敗した場合、未再開の専用プロセスだけをハンドルで終了して BLOCKED と記録する。

通常の停止要求は各試行固有のファイル作成で通知する。読取側は受領を記録して通信を閉じる。非協力対照では受領を記録して処理を継続する。監督側は専用 Job の稼働を確認後、猶予満了時に TerminateJobObject を要求する。要求の発行、OS ハンドルのサイン、残存確認、回収完了を個別に採時する。

## 試行順と境界

| 試行 | 条件 | 接続上限 | 通常停止予定 / 強制停止予定 | 回収上限 | 事前期待 |
| --- | --- | ---: | ---: | ---: | --- |
| normal | HTTP 200、原バイト一致 | 10 s | 24.50 / 24.75 s | 25 s | 正常 |
| missing | HTTP 404、空本文 | 10 s | 24.50 / 24.75 s | 25 s | 明示不存在 |
| connect-short | CONNECT 応答を止める短縮対照 | 1 s | 接続期限 / +0.25 s | 2 s | 接続期限 |
| body-short | HTTP 200、断片送信後に停止 | 1 s | 1 / 1.25 s | 2 s | 通常停止で回収 |
| connect-10 | CONNECT 応答を止める実時間対照 | 10 s | 接続期限 / +0.25 s | 25 s | 接続期限 |
| body-25-reserve | HTTP 200、断片送信後に停止 | 10 s | 24.50 / 24.75 s | 25 s | 通常停止で回収 |
| ignore-stop | 断片送信、通常停止を受領して無視 | 10 s | 24.50 / 24.75 s | 25 s | 強制停止で回収 |
| process-tree | 同上、子を1つ生成 | 10 s | 24.50 / 24.75 s | 25 s | 親子を強制停止して回収 |
| near-before | 起動から24.20 sで本文末尾を解放 | 10 s | 24.50 / 24.75 s | 25 s | 正常回収 |
| boundary-25 | 起動から25.20 sに本文末尾を解放する予定 | 10 s | 25 / 25.25 s | 25 s | 期限超過 FAIL の対照 |

監督が CreateProcess を呼ぶ直前を t0 とする。各予定は t0 からの絶対単調時刻。短縮対照以外の接続上限10秒と回収上限25秒を維持する。回収予算付き条件は通常停止に0.25秒、強制停止発行から回収上限までに0.25秒を確保する。25秒発火対照には回収の許容超過を足さない。接続段階では読取側が絶対接続期限を使い、期限後にトンネルが成立しても GET を開始しない。監督は接続が未成立なら接続期限から停止を要求する。

回収完了は、監督が保持する親子ハンドルの終了、Job の稼働数ゼロ、ハンドル閉鎖、IPC 治具終了、記録と応答原バイト回収を全て観測した時点。原票の JSON 直列化と永続コピーは計測外。実測の上限超過、残存、期待と異なる応答は FAIL。機能や権限の制約は BLOCKED、終了や証拠を確認できない場合は UNKNOWN、未起動は NOT_TESTED。停止後に受理できる正常本文は存在しない。回収時刻は丸め前の nanosecond 値で評価する。

試験コードと本計画の SHA-256 および UTC を各 run 開始時にロックし、再試行は別 run ID を使用する。原票と停止・回収ログは新規ファイルにのみ書く。GitHub の提出と承認済み保全先への保存、そこからの独立再取得を別の証拠とする。
